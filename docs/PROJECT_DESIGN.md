# 项目设计说明与代码审核

当前工程是 C++20、60Hz、服务端权威的双人迷宫对战 Demo，v6 支持独立房间、凭证重连、可复现数据报实验、独立显示状态和原始浮点回放。具体源码阅读顺序及同步时序见 [架构指南](ARCHITECTURE.md)，运行命令见 [README](../README.md)，实测记录见 [升级报告](UPGRADE_REPORT.md)。

## 代码审核结论

2026-10-05 的轻量整理仅补充注释和文档，其后本轮按六阶段计划实施行为升级。原工作区的构建配置、图片、历史报告、vcpkg/presets 文件及既有权限保留；未新增生产依赖，未提交或撤销无关修改。

| 检查项 | 当前实现依据 | 影响及验证 |
| --- | --- | --- |
| 校验前修改世界/连接 | `Protocol::Decode` 完成长度、值域、地图、量化哈希检查；`ClientSession::HandleDatagram` 校验来源/身份；`RoomServer::HandleDatagram` 最后提交地址、活动时间和输入 | **已修复并回归**：坏包不提交世界、预测依据、连接或活动时间；拒绝统计允许增加 |
| 历史不足与未来快照 | 校正前遍历完整输入区间，限制 120；未来状态重设 `nextTick` | **已修复并回归**：历史覆盖触发 Resynchronizing，不填空输入；未来状态不再模拟旧帧 |
| 回绕、重复与迟到 | `Distance/Newer` 使用模 2³² 差值，帧/序号/控制请求共用；分开 duplicate/late | **已修复并回归**：跨 UINT32_MAX 重放；旧进度不回退；重复控制请求不增加代次 |
| 重连身份和重启 | instance/room/match/session/generation/player 与 token；一秒静默重握手、十秒保留 | **已实现并回归**：三秒断线原局恢复、旧代次拒绝、过期结束及实例重启重新握手 |
| 席位到期后的剩余客户端 | End 后保留自身凭证回到等待，服务器拒绝同地址无凭证重复占槽 | **测试发现并修复**：避免一个剩余玩家占用两个槽位，形成自己与自己对局 |
| 资源释放 | base 最先创建最后析构，事件先释放；socket 拥有读事件；SDL/TTF 由上下文清理 | **Sanitizer 回归通过**：正常退出、UDP 生命周期及字体初始化失败。macOS 不以 LeakSanitizer 报告证明零泄漏 |
| 推箱墙体约束 | `World::Step` 固定四轮，每次推箱候选位置使用移动相同的分轴碰撞约束 | **贴墙回归通过**：空间不足保留重叠，不能推入墙体；有限轮数使重放成本有界 |
| 初始化与迟到控制回复 | Welcome/Sync 都有完整状态及 `nextTick=completed+1`；首帧 0/1；正在比赛时忽略迟到 Welcome | **已实现并回归**：没有首帧偏移或隐含倒计时，迟到控制包不能回到旧等待状态 |
| 初始 RTT 与重连时间戳 | 控制回复回显发送序号；控制/输入时间戳分开存储，新代次清理旧输入时间戳 | **检查发现并修复**：握手取得初始延迟，重连不会采用旧 ACK 时间；两组性能代码包含相同修复 |
| 地图复制与历史读取 | StateHistory 存动态状态，按完整地图值选择 shared const map；GetView 读取不复制 | **保留的测量优化**：完整 Get/export 保持值语义，字段/哈希顺序保持；分配约降 7%，64 房间 RSS 约降 18%–19%，CPU 收益依场景波动 |
| 真实 UDP 容量 | bot 复用 ClientSession，运行逻辑复用 ServerRuntime | **独立测量**：核心与真实 UDP 分开，不能把旧版离线容量直接当新版服务端容量 |

不把静态风险当作已经复现的缺陷：跨平台原始浮点确定性、公网 MTU/突发拥塞、长时间高负载和恶意流量鲁棒性仍需专项验证。身份凭证用于会话恢复和旧包隔离，不等于公网认证。

## 模块与所有权

| 模块 | 职责 | 依赖/所有权 |
| --- | --- | --- |
| World / Hasher / histories | 固定帧模拟、完整恢复、毫米哈希、环形历史 | 容器值与共享只读地图；没有传输层或 SDL |
| ClientSession | 输入、预测、身份、校正、时序、显示副本、统计与待发送数据报 | 时间与来源由外部注入，拥有客户端状态 |
| RoomServer | 路由独立双人房间、权威推进、输入校验、生命周期、重连、实际输入观察器 | 拥有房间与席位；身份随机源可注入 |
| ServerRuntime | UDP 收发与固定帧实际调度 | 拥有 socket；libevent base 是借用对象 |
| NetworkSimulator | 双向延迟/抖动/丢包/乱序/重复、稳定事件排序、轨迹 | 虚拟单调时间、固定 PRNG；所有控制和玩法包走同一路径 |
| ReplayWriter / ReplayPlayer / ReplayPlayback | 版本化落盘、顺序验证、首字段差异、窗口播放控制 | 原始浮点初值和实际采用输入；暂停不累积模拟时间 |
| SDL 入口与 ClientRender | 键盘、显示、HUD、回放按键 | SDL/TTF 上下文统一清理；显示位置不回写世界 |

`World::Step` 是唯一模拟推进入口。服务端保留权威结果，客户端不能上传世界覆盖它。对局内没有数据库、Redis、后台任务或全局单例；进程内房间状态按身份管理，持久化采用顺序回放文件。需要账号、匹配或战绩时，应在对局外增加服务，不能把数据库读取加入每帧推进路径。

## 同步策略与设计取舍

固定步长让恢复点、输入和历史共用离散帧索引；真实时间只调度调用次数。初始化完成帧 0，输入帧 1。普通快照永远是已完成帧，不会重放权威帧本身。

输入包带最近四帧冗余；服务端按完整帧号读取，缺失保持至多六帧后归零。迟到输入不会使权威服务端回滚。客户端远端移动来自快照推测，远端攻击与命中采用权威状态。

校正每个有效新快照，区间是 `auth+1 .. localNext-1`。先检查所有本地输入存在，最多 120 帧；不足时停止预测请求完整恢复点。合法未来快照直接推进下一编号。客户端根据 ACK/RTT 与 64 样本抖动余量控制 2–10 帧领先，每次至多补四帧。

显示平滑与模拟分离：本地位置偏移百毫秒衰减，超过两米及完整重同步直接采用新位置；远端位置延迟百毫秒插值。HP、动作、命中字段保持离散。开关平滑不会影响模拟哈希。

v6 使用有界 JSON 数据报和显式控制请求，便于教学、诊断及轨迹检查；全量地图/状态的带宽成本会被报告。编码和解码都限制边界；不能截断数量后继续计算哈希。完整地图由服务端下发，避免不同标准库的随机地图生成差异。

回放保存**实际应用**输入，包括缺失后的保持/空输入；初始化与期望状态保存原始 float 的可往返表示。网络毫米量化不能作为原始回放初值。未支持版本、非法记录与缺少结束记录分别报错，首次字段分叉停止播放。

## 后续优化方向与优先级

六阶段功能完成后的方向仍按正确性 → 测量 → 体验/扩展推进：

| 优先级 | 代码依据与方向 | 影响与下一项验证 |
| --- | --- | --- |
| P1 | 64 房间 UDP 的第三轮 deadline miss 0.167%，超过 0.1% 预算 | 独立采样服务端及编码/发送分段，扩大长尾观察；64 上限不等于稳定容量，先定位后决定过载策略 |
| P1 | Protocol 的有界 JSON 解析、控制身份与序号窗口继续做生成式畸形数据报测试 | 扩大嵌套、边界整数、跨代次乱序覆盖；检查拒绝后状态和有效活动时间不变 |
| P1 | RoomServer 的席位、录制确认与输入窗口做更长时间组合实验 | 组合超宽限断线、控制包持续丢失、地址切换、记录积压；保存首个失败轨迹 |
| P1 | 原始 float 回放在其他编译器/平台对照 | 按首字段定位分叉，先量化风险再决定定点化；不以毫米哈希掩盖原始差异 |
| P2 | Protocol 全量地图、JSON 对象构造及编码成本 | 固定录制设置测量字段/分配/字节；仅保留有收益的缓冲复用，带宽成为瓶颈后单独设计增量协议 |
| P2 | ClientSession/RoomServer 统计容器和运行时输出 | 测量长局内存及诊断开销；保留必要采样，避免为了性能破坏失败现场可复现性 |
| P2 | ServerRuntime 单线程房间调度的截止时间 | 以真实 UDP 多轮 P99/miss 判容量；超预算时先做可测量的过载策略，不能用平均值声称稳定 |
| P3 | Display 插值与本地偏移的视觉反馈 | 使用相同网络种子、平滑开关和窗口录屏，分析跳变/输入显示延迟；显示优化不得改变哈希 |
| P3 | 回放索引、观战、房间服务生命周期接口 | 首版顺序回放验证稳定后再加跳转/观战；账号、匹配和公网认证另立范围 |
